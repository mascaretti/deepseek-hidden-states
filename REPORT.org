#+TITLE: Repository Audit Report: =deepseek-hidden-states=

* 1. Executive Summary

This repository implements experiments for measuring *Information Imbalance (II)* and *CKA (Centered Kernel Alignment)* between hidden-state representations of different neural networks (DeepSeek-V3, LLama-3.1-8B, CLIP, DinoV2, ImageGPT). The codebase has grown organically across multiple HPC environments and collaborators, resulting in significant duplication, dead code, and entangled concerns. This report catalogues every file, classifies it as *actively used*, *superseded*, or *orphaned*, and proposes a cleanup plan.

* 6. Key Issues

** 6.1 Massive Code Duplication
The =collect_data()=, =collect_images()=, =CPU_Unpickler=, and =compute_inf_imb_matrix()= functions are *copy-pasted* across 7+ files:
- =check_asymmetry.py=
- =check_asymmetry_images.py=
- =check_mean_asymmetry.py=
- =compute_information_imbalance.py=
- =compute_information_imbalance_images.py=
- =compute_information_imbalance_imageimage.py=
- =compute_information_imbalance_images_jackknife.py=
- =compute_platonic_images.py=

=compute_asymmetry_unified.py= was written to replace all of these, but the old files were never removed.

** 6.2 Two Distinct II Implementations
1. *=information_imbalance_module.py=* (local, JAX-based): Used by all compute scripts in the repo.
2. *=information_imbalance= package* (installed, NumPy-based): Used by =20251201_mat_asymmetryII.py=, =20251201_mat_gaussianII_infoimb.py=, =20251201_mat_gaussianII_combined.py=.

These have different APIs (=build_information_imbalance= in the local module returns =(forward, backward)= tuple; the package version takes =k=, =maxk=, =subset_size= parameters). This split is undocumented and confusing.

** 6.3 Two Distinct II Computation Approaches
- *Old approach* (=build_information_imbalance=): Returns scalar II values directly. Used by the old =compute_information_imbalance*.py= scripts.
- *New approach* (=build_information_matrix=): Returns raw ranks/cards for post-hoc bootstrap. Used by =compute_asymmetry_unified.py= and the =check_asymmetry*.py= scripts.

** 6.4 Hardcoded Paths Everywhere
Server-specific paths (=/home/mascaretti/=, =/home/laios/=, =/home/rende/=) are hardcoded in nearly every script and entry point. Three different users' home directories appear:
- =/home/mascaretti/= (primary user)
- =/home/laios/= (shared data/results)
- =/home/rende/= (collaborator)

** 6.5 No Dependency Management
No =requirements.txt=, =pyproject.toml=, or =setup.py=. Dependencies are scattered and unclear. Known dependencies include: =jax=, =torch=, =safetensors=, =einops=, =tqdm=, =scienceplots= (optional), =sglang= (for extraction only), =transformers= (for extraction only), =information_imbalance= (installed package, used by some scripts).

** 6.6 =platonic.py= Duplicates and Extends =information_imbalance_module.py=
=platonic.py= contains a full copy of the II computation logic *plus* mutual k-NN alignment. The shared functions (=pairwise_distances=, =separate_samples=, =mapped_compute_ranks=, etc.) diverge slightly from =information_imbalance_module.py=.

** 6.7 Script Generates Scripts
=run_all_multilayer_analysis.py= and =run_overnight_analysis.sh= dynamically generate Python scripts as strings and execute them. This is fragile and hard to debug.

** 6.8 No Tests
No unit tests, no CI. The =test_*.py= files are ad-hoc verification scripts, not proper tests.
